주제별로 md파일까지 포함해서 커밋하고 푸시해줘.
커밋 메시지는 반드시 한국어로, 아래 커밋 타입 컨벤션을 따라 작성해.

## 커밋 메시지 형식

`Type: 한글 설명`

## 커밋 타입 목록

| Type | 설명 | 참고사항 |
|------|------|---------|
| Feat | 기능 추가 | 기능 당 최초 한 번만 사용 |
| Build | 라이브러리 세팅/업데이트 | 라이브러리 설치 최초 한 번만 사용 |
| Update | 라이브러리 버전 업데이트/커스텀 | |
| Config | Config 파일 설정 | |
| Remove | 파일 삭제 | |
| Fix | 기능 에러 수정 | |
| HotFix | 치명적인 버그 수정 | main 브랜치에 바로 반영 |
| Style | UI 관련 CSS 수정 | |
| Chore | 단순 코드 수정 | 주석, 줄 바꿈, 임포트문, 세미콜론 등 |
| Revise | 기능 추가나 덧붙임을 위한 수정 | |
| Typo | 오타 수정 | |
| Modify | 기능 변경 있는 코드 개선/변경 | |
| Refactor | 기능 변경 없는 코드 개선 | |
| Asset | 이미지, 폰트 | 리소스 파일 |
| Docs | 문서 작성 | |

## 예시

- `Feat: 전자문서 열람 서명 기능 추가`
- `Fix: PDF 생성 시 한글 깨짐 수정`
- `Docs: 전자문서 법률 검토 문서 작성`
- `Style: 랜딩 페이지 반응형 CSS 수정`

## 푸시 전 빌드 검증 (필수)

푸시하기 전에 반드시 `npm run build`를 실행하여 Vercel 배포 오류가 없는지 확인해.
- 빌드 에러가 있으면 **에러를 수정한 뒤** 푸시해.
- TypeScript 타입 에러, import 누락, 미사용 변수 등 빌드 실패 원인을 모두 해결할 것.
- 빌드 성공 확인 후에만 git push를 실행해.
